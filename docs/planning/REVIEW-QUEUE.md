# Review Queue

Cross-week state for the recurring **Weekly Reviews** batch (see WEEKLY.md → Recurring Weekly Reviews / Group WR). Each week, per category, use **hybrid sourcing**: fresh-check the live landscape (a `WebSearch` for the current best, excluding the Reviewed log) **and** consider the parked **Next-up** item, then review whichever is strongest — do not rote-pick the parked item. Use **lightweight inline research** (a few `WebSearch` + 2–3 `WebFetch`; never the deep-research harness for a routine review). Append a verdict row (`adopt | pass | defer`); park notable runners-up under **Next-up**. On an `adopt`, also file a 🟤 Auto-Generated entry in BACKLOG.md **and name its trial vehicle** — see [§ 5. Adopt trials](#5-adopt-trials) for the policy and the outcome log.

**Sections 1–3 are inbound** (external candidates reviewed for use here). **Section 4 is outbound/inbound propagation** and uses a different verdict vocab (`propagate | pass | defer`) with a different routing sink (`TODO.md` § Spawned Tasks) — its conventions are stated in that section.

## 4. Cross-project propagation

**Added 2026-08-27** (WEEKLY.md G5). Unlike sections 1–3, this section's candidates are **not external

invented here — one convention, two directions.

### Conventions

- **Verdict vocab is `propagate | pass | defer`** (not `adopt`).
- **Row (outbound)**: `YYYY-MM-DD — <learning/origin> — verdict: … — note`.
- **Row (inbound)**: `YYYY-MM-DD — <origin repo / source> — <per-item status> — note`. An inbound
  sweep covers several items at once, so the status is stated **per item** inside the row rather than as a
  single trailing verdict.
- **`propagate` → file a row in [`TODO.md`](TODO.md) § Spawned Tasks** — the outbound analog of
  `adopt` → 🟤 BACKLOG. `pass`/`defer` stay in this file.
- **Verify against the target; never assume.** Confirm a learning is absent from the destination by
  grepping the specific strings there. Diffing trees is meaningless — they are scrubbed and drift by
  design.
- **Direction (D1, this repo's deviation).** WEEKLY.md defines only the outbound half. This section is
  **bidirectional**, because the sibling repo already carried unactioned rows addressed to
  media_viewer that a one-way channel would have dropped permanently.
    - **Outbound** — what shipped _here_ since the last run that belongs elsewhere.
    - **Inbound** — what another repo has already routed _at_ this one. An inbound item is actioned only
      once its **origin repo's own review is complete**; until then it is recorded and parked, not filed
      as work.
- **Target scope (D2)**: `~/.claude` via `claude-code-universal-config` is the one **confirmed**
  standing target. `wallpaper_sorter`, `media_compression`, `media_parser` are **TBD** — not yet
  established as propagation partners; decide before treating them as targets.
- **Scan window** = since the previous run's date, not "this week".

## 5. Adopt trials

**Added 2026-08-30** (WEEKLY.md G4). Sections 1–3 produce `adopt` verdicts; until now nothing recorded
what happened next, so an adopt had no terminal state. This section closes that loop. Frozen
Reviewed-log rows are never rewritten — a trial outcome lands here and cross-refers to its verdict date.

### Policy (decided 2026-08-30 — option **b+**)

- **An `adopt` MUST name its trial vehicle** — the specific PR, session, or measurement that will
  exercise it — at the moment the verdict is filed. A candidate with no nameable vehicle is filed
  `defer`, not `adopt`. Reviews stay hands-off (D4 unchanged: file the entry, install nothing); what is
  new is that a verdict must state _how it would ever be consumed_.
- **Trials run in batches**, in Cleanup Weeks by default, and each writes a row to the log below.
- **Queue cap**: while more than **3** adopts are outstanding (filed, no outcome row), a new candidate
  is parked under its section's **Next-up** instead of being filed as `adopt`.
- **Not every `adopt` is a trial.** An adopt that is simply implementation work with a known shape (the
  path-scoped-rules migration, for one) is ordinary 🟤 BACKLOG work and does **not** belong in this log.
  The log is for candidates whose value is uncertain until exercised — tools, plugins, practices.
- **Cadence: weekly, as written** — reaffirmed 2026-08-30 rather than re-timed to the observed average.
  Recorded as a watch, not a re-litigation: the first three runs landed 2026-06-26 → 07-05 → 08-27,
  three runs in ten weeks. If a fourth long gap opens, re-open the cadence question with that as the
  evidence rather than absorbing the slip.

**Why this exists.** The 2026-08-27 run recorded `adopt` verdicts with zero trial outcomes and diagnosed
it as _"a review process whose output is never tried produces verdicts, not value"_. The measured cause
was not neglect: `pr-review-toolkit`'s vehicle was "a real PR", and the PR it waited on never opened —
G1 merged locally as `66b16af`. A vehicle that names nothing in particular is how an adopt becomes a
permanent resident.
