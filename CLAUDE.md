# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

**Media Viewer** - Electron desktop application for browsing, rating, and managing media files (images and videos) with visual similarity sorting and ML-based prediction features.

Key capabilities:
- Browse media folders with image/video preview
- Rate files (like/dislike/special) with keyboard shortcuts
- Visual similarity sorting using perceptual hashing and CLIP semantic embeddings
- ML-based prediction for user preferences
- Face detection features

## Build & Development Commands

```bash
npm install            # Install dependencies
npm start              # Run the application (also: npx electron .)
npm test               # Unit tests (Vitest)
npm run test:e2e       # E2E tests (Playwright + Electron)
npm run lint           # Lint all JS (lint:fix to auto-fix)
npm run format         # Prettier (format:check to verify only)
```

`MV_USER_DATA_DIR=<dir>` runs the app on another profile folder. Use it on a copy of the real profile (`%APPDATA%\media_viewer`) for a pre-merge manual test of anything that migrates stored state.

Pre-commit hook (Husky): `node scripts/check-secrets.js` (staged-diff secret scan) → `node scripts/check-docs-index.js` (whole tree, not just staged files: every file under `docs/archive/plans/` and `docs/superpowers/specs/` must be linked from `docs/README.md`, and every link must resolve) → `node scripts/check-claude-md-size.js` (warns, never blocks, when the staged `CLAUDE.md` grows past its limits) → lint-staged (ESLint --fix + Prettier on staged `*.{js,cjs}`, Prettier only on `*.{json,css,html}`) → `npx vitest run` (unit tests must pass). E2E is NOT run by the pre-commit hook. Pre-push hook (Husky): `node scripts/check-e2e-needed.js` decides RUN or SKIP for the outgoing range (SKIP only when EVERY changed path is `*.md` or under `docs/`; any failure falls back to RUN); on RUN the hook runs the full Playwright E2E suite. **Per-check bypass**: `SKIP=<check>[,<check>…]` waives the named checks for one command and warns on every skip — pre-commit tokens `secrets`, `docs-index`, `lint-staged`, `vitest`; pre-push `e2e` (shared helper `.husky/skip.sh`; PowerShell: `$env:SKIP='docs-index'; git commit …; $env:SKIP=$null`). `--no-verify` is the last resort: it disables every check, the secret scan included.

**Data Flow**:
1. Main process: file system ops, JXL decode support (`read-file-buffer`, `read-jxl-wasm`), CLIP model inference, tournament state (`.tournament_state.json`), bulk-rated cache (`.bulk_rated.json`), feature-cache streaming (stream-json parse + batched atomic writes), atomic folder-cache and bulk-rated writes
2. Preload exposes a secure IPC bridge to the renderer (`onClipDownloadProgress` returns a cleanup function)
3. Renderer (media-viewer.js) manages UI state; calls CLIP via `window.electronAPI`; TournamentManager delegates IPC
4. CPU-intensive work → Web Workers (sorting, ML, feature extraction); CLIP is main-process IPC (§ Active gotchas)

## Code Conventions

**Naming**: Functions camelCase verb-first (`loadMedia`); Classes PascalCase (`MediaViewer`); Constants UPPER_SNAKE_CASE; DOM IDs kebab-case; CSS classes kebab-case.

**Patterns**:
- Core UI logic in `media-viewer.js` (MediaViewer class). v2.0 modularization extracts subsystems into dedicated modules (FullscreenManager, TournamentManager, MlTrainingManager, FeatureCacheStore): stateful manager class + constructor-injected host callbacks; MediaViewer delegates via `this.fullscreen.toggle()` etc. `MlTrainingManager` owns training-set assembly, the fingerprint, and the training-vector/model caches — sort orchestration and the progress card stay in the renderer (`handleSortByPrediction`/`updateSortProgress`).
- IPC: main process does file ops, renderer does UI. Event-driven. CPU-heavy work in Web Workers. Centralized cleanup methods (file removal, cache cleanup).

**Imports**: CommonJS `require()` in main process and workers; browser globals in renderer (no bundler); ES module `import` in media-viewer.js for extracted modules (`fullscreen.js`, `tournament.js`, `ml-training.js`, `feature-cache-store.js`).

**Unused variables**: prefix with `_` to satisfy ESLint `no-unused-vars` (`varsIgnorePattern`/`argsIgnorePattern`/`caughtErrorsIgnorePattern: '^_'`).

**Formatting & Linting**:
- Prettier: tabWidth=4, useTabs=false, singleQuote, semi, trailingComma=es5, printWidth=120, bracketSpacing, arrowParens=always, endOfLine="lf". `.gitattributes` enforces LF.
- ESLint flat config (`eslint.config.mjs`): one block per file group; shared rules eqeqeq/curly/prefer-const/no-var/no-shadow(warn)/no-unused-vars(warn); `eslint-config-prettier` last. A main.js-only object bans bare `ipcMain` registration, and the renderer blocks share `htmlSinkGuard` (no built string reaches `innerHTML`/`outerHTML`/`insertAdjacentHTML`/`document.write`). Flat config replaces a rule's options per object, so merge into that array; `tests/lint-guard.test.js` proves both rules fire.
- Prettier ignores `docs/`, `*.md`, `package-lock.json`.

**Testing (Unit — Vitest)**:
- Config `vitest.config.js`; tests in `tests/**/*.test.js` excluding `tests/e2e/**`.
- CJS modules in ESM tests: `createRequire(import.meta.url)` then `require('../module')`. Pure-ESM modules (`tournament-engine.js`, `ml-training.js`) import directly. Web Worker modules: stub `globalThis.self = { onmessage: null, postMessage: () => {} }` before `require()`.
- MediaViewer method testing: `extractMethod(name)` / `extractAsyncMethod(name)` read source, extract the method body by brace-counting, and return a `Function`/`AsyncFunction` invoked via `.call(mockCtx, ...)`. The mock ctx must supply every `this.*` the method touches (e.g. `removeFileFromList` needs `clipCache`/`jxlFrameCache`/`bulkRated` Maps + `bulkRatedPairs` Set + `saveBulkRatedFile`). Replicate heavy-DOM algorithm logic as standalone helpers (see `ml-pair-selection.test.js`).
- Globals/time: patch `globalThis.localStorage`/`globalThis.window` in `beforeEach`/`afterEach`; `vi.useFakeTimers()`+`vi.setSystemTime()` for time.
- Worker abort flag (**`sorting-worker.js` only** — `ml-worker.js` has none, deliberately; its dispatch comment says what re-adding one would cost) is not directly accessible — set via `self.onmessage({data:{type:'abort'}})`, reset via a `resetAbort()` helper sending an unknown-algorithm `startSort` (handler resets the flag before the switch). It is the worker's message contract only: the renderer no longer posts `abort`, and `runSortingWorker` terminates the worker instead. Prefer exact `.toThrow('message')` over regex to catch message drift.
- `TournamentEngine.undo()` test mocks must set `Object.setPrototypeOf(mock, {constructor: StrategyClass})` and `StrategyClass.deserialize = vi.fn()` (undo calls `StrategyCtor.deserialize`).

**Testing (E2E — Playwright)**:
- Config `playwright.config.js`; workers:1, fullyParallel:false (Electron can't parallelize).
- Electron 30+ workaround: `electron-wrapper.cjs` strips `--remote-debugging-port=0`, re-applied via `rdp-preload.cjs` (playwright#39008); unset `ELECTRON_RUN_AS_NODE` before spawn. `rdp-preload.cjs` loads playwright-core `loader.js` by path — update if it breaks after upgrade.
- `.media-container` overlay blocks pointer events — use `{force:true}` or `page.evaluate()`.
- Helpers: `seedLocalStorage(page, kv, { grant = true })` (call after `launchApp()`, before `loadFolder()`; it grants the three folder keys in main first, while `{ grant: false }` seeds a folder main never granted, like one saved before G1); `grantFolder(app, path)`; `mockFolderDialog(app, path)` (grants the pick and records the dialog's `defaultPath` in `global.__mvLastDialogDefaultPath`); `loadFolder` grants first. Each `launchApp()` gets a fresh grant store via `MV_E2E_GRANTS_FILE`, exposed as `global.__mvGrants` to `electronApp.evaluate` only; `closeApp()` (races close vs 5s then SIGKILL; Windows `taskkill /F /T`); `createTempFixtureDir(names?)`. `launchApp({ migrationMarker })` sets `MV_E2E_MIGRATION_MARKER`; by default it points at a pre-written marker, so the one-time `localStorage` migration is skipped. `global.__mvAppProtocol` (with `__mvGrants`) exposes the app scheme handler's `openStreams()` to `electronApp.evaluate`. `closeApp` also clears `recentFolders`, and `launchApp` clears it at start; `mockFolderDialog` counts opens in `global.__mvDialogCalls` (reset on each install).
- `afterEach` null guards: guard `if (electronApp)`/`if (tmpFixtures)`/`if (page)` before cleanup (`.catch()` only handles rejections, not a sync TypeError on undefined).
- Before a method that guards on `isLoading` and `mediaNavigationInProgress` (e.g. `handleCancel` after `applyBulkRating`), `await page.waitForFunction(() => !window.mediaViewer.isLoading && !window.mediaViewer.mediaNavigationInProgress)`. The latter flag is set by `showMedia()` for the duration of its own render (e.g. `applyBulkRating`'s fire-and-forget call) without setting `isLoading`.
- `mlWorker` is **lazy** (`initializeMlWorker()` runs on the first AI sort / settings toggle) — an E2E that needs real scoring must call it, override `getCombinedFeatures` with **576-dim** vectors, and warm the model via the same `trainHistorical` round trip production uses (`_runWorkerTraining`, ≥3 likes + ≥3 dislikes — `ml-worker.js`'s `scoreFiles()` replies `scores: null` below that threshold). Forcing `isSortedByPrediction = true` alone leaves `mlWorker` null and proves nothing. A bulk rating or its undo posts **nothing** to the worker for the rating itself and renders immediately; `compare-mode.test.js`'s real-worker test proves this by instrumenting `mlWorker.postMessage` (`window.__postedTypes`) and `showMedia()` (`window.__showMediaCalls`) on a live, warmed worker.
- An E2E that chains file actions must let the previous one finish first (the file-op guard refuses an overlapping one, § Async Patterns) — waiting for no `isLoading`/`mediaNavigationInProgress` after its render is enough, since `_fileOpInFlight` drops before the render it starts settles.

## Detected Patterns

**Error Handling**: user-facing errors via the notification system (bottom-right); renderer errors forwarded to the main-process file logger via `window.electronAPI.logError` (fire-and-forget), which accepts a plain string or `{ level, message, source }` — `main.js` normalises both via `logger.normalizeRendererLogEntry`; `showError()`, `window.onerror`, `unhandledrejection` all forward. `showNotification(…, { sticky: true })` stays until closed, is exempt from the 5-notification and info prunes, and leaves its action button's closing to the caller. `showNotification` returns its element.

**Data Structures**: MinHeap (priority queue) and VPTree (nearest neighbor) live only in `sorting-worker.js`: sorting is worker-only. Perceptual hashing (image similarity), cosine distance for CLIP (`1 - dot(a,b)` on unit-normalized 512-dim). `calculateCosineDistance` exists in both `sorting-worker.js` and the `MediaViewer` class — the renderer copy returns `1` (not `Infinity`) on null/mismatched input (cosine is bounded [0,2]; 1 = "no signal").

**State Management**:
- Class-based state in MediaViewer; localStorage for prefs (constructor validates/clamps). Settings panel (F1); `enableClipFeatures` (default true) toggles CLIP (~87 MB model on first use). On CLIP disable: revert `sortAlgorithm`→`'vptree'` + sync dropdown SYNCHRONOUSLY, THEN `await deleteSortCache('clip')` (also `clearTimeout(clipUnloadTimer)`) — order matters to avoid a stale-state transient.
- Empty state: `showEmptyStateWithUndo()` (preserves undo toolbar) vs `showDropZone()` (genuine empty) by `moveHistory.length`; empty-state keydown guard blocks all keys except undo, and its `canUndo` predicate is a disjunction — `moveHistory.length > 0` **or**, in tournament mode, `engine.peekUndoKind() != null` (a tournament emptied purely by the `-1` auto-prune writes nothing to `moveHistory`). The `isTournamentMode` conjunct is load-bearing: without it a stale `engine.history` would let a single-mode undo call `handleCancel` against an empty `moveHistory`.
- **Like-or-skip**: `this.likeOrSkip` (`LikeOrSkip.SkipTracker`) records the file each single-mode Next leaves while the AI order is on screen. Its `active` flag is that token — not `isSortedByPrediction`, which the similarity sort leaves set. Every method that puts a new ORDER of `mediaFiles` on screen (reassigns it) goes through `_onOrderChanged(kind)` — in-place splices/pushes by moves and undos are not announced: `'ai-fresh'`/`'ai-resort'` turn tracking on (skips emptied/kept), `'other'`/`'folder'` turn it off; it also bumps `_orderGeneration`. `tests/like-or-skip-glue.test.js` fails on a new `this.mediaFiles =` outside its reviewed lists (it matches those assignments only). The out-of-date chip (`_updateResortChip()`) counts by entry identity against a snapshot of `moveHistory` taken before training (`LikeOrSkip.computeStaleCount`) — no undo hook. Design: [G2 spec](docs/superpowers/specs/2026-10-12-g2-like-or-skip-flow-design.md).
- **Recently opened folders**: `this.recentFolders` (localStorage `recentFolders`, cap 8, exact-path identity) is recorded only by `loadFolder`'s non-empty success branch and changed only through `_setRecentFolders` (persist in try/catch → re-render). Rendering asks main nothing — a status query on an offline share holds main ~21 s; a folder is checked when it is chosen. The list's parse and clamp (`RecentFolders.parseRecentFolders`) are hygiene; main's `kinds.grantedPath` is the boundary. A click goes through `openRecentFolder(path, surface)`: single-flight, refused during a file action, then grant status → exists (`classifyRecentFolder`); the clicked row reads "Checking…", never the spinner (which hides the drop zone). The UI stays live during the check, so a stale decision is dropped: `_folderIntentGen` is bumped by `openFolderDialog` and the change-folder handler (each before its dialog) and by `loadFolder` (after its refusal), and when it moved across the check's awaits `openRecentFolder` abandons 'open' and 'regrant' silently ('missing' and 'unreachable' still apply); 'regrant' also re-checks the file-op guard before its dialog. **One folder load at a time**: `loadFolder` holds `_folderLoadInFlight` until it settles, and while it is set `_refuseIfFolderLoadInFlight()` refuses `loadFolder`, `switchToFolder`/`_switchToFolderNow` (before the reset), `openRecentFolder`, change-folder (before its dialog), the similarity Restore Order, the similarity offer's Show and the AI sort (start and toggle-off), and ▾ is disabled. Two overlapping loads save one folder's ratings into another's `.bulk_rated.json`: the older load's `loadBulkRatedFile` read resolves against `this.mediaFiles`/`baseFolderPath` after its await. Design: [G4 spec](docs/superpowers/specs/2026-10-16-g4-recently-opened-folders-design.md).
- Compare-pair undo: history entries tagged `compareMode:true`; `handleCancel()` checks bulk-rating undo FIRST (`lastMove.bothGood || lastMove.bothBad` → `undoBulkRating`), then compare-pair. A `skipBatch` entry (bulk dislike) goes to `_undoSkipBatch` beside the bulk check: exact original positions when `entry.orderGeneration === _orderGeneration`, else parked at the front; positions shift past files that failed to come back, which are pushed back as a smaller entry — or, when nothing came back, the same entry object (the out-of-date count is by identity). The compare-pair branch pops two entries only when the top two are both `compareMode`, so an orphan compare entry above a batch is undone alone. A `skipBatch` undo is refused ("Wait for the sort to finish") while a sort runs, like the batch itself.
- `resetMlModel()` nulls `mlModelState`/`mlStats`, resets `predictionScores`, **nulls `mlTraining.sessionFingerprint`/`sessionStats`**, and posts `{type:'reset'}` to `mlWorker`. The session-tier clear is load-bearing: `{type:'reset'}` zeroes the worker's weights AND both class counts, while `ensureTrainedModel` resolves its `session` tier by fingerprint equality alone — and every call site returns the descriptor to the *same* fingerprint, so leaving it set makes the next sort reuse an empty model (`scores: null` for the rest of the session). Call sites: the four like/dislike folder controls (browse/clear × like/dislike), the CLIP toggle, and the Settings "Rebuild model" handler (`handleRebuildModelClick`, after `mlTraining.invalidateModelCache()` clears the fingerprint-keyed model cache). `loadFolder()` deliberately does **not** call it: the model's identity follows a training-set fingerprint (keyed on the like/dislike folders + bulk-rated files — not the folder being viewed), so switching only the source folder must never discard a still-valid trained model. `initComplete`'s `modelWasReset` (worker-side version/dim mismatch) separately clears `mlModelState`/`predictionScores` in memory only.
- `predictionScores` sync: `applyPredictionSortResult(result)` (`{ resort }` on a chip re-sort — `handleSortByPrediction({ resort: true })` skips the toggle-off, keeps `originalMediaFiles`, and the result parks un-disliked skips first with the cursor on the first unjudged file) — called from `handleSortByPrediction` Phase 3 (after `await runMlSort`), NOT from the `sortComplete` handler (that only resolves the pending promise) — writes `result.scores` (filename→score) into `predictionScores` before reassigning `mediaFiles`, so badges match the sorted order (guarded `if (result.scores)`).

**Index Management**: `moveCurrentFile()` wraps to 0 on the last file; `removeFileFromList()` caps to length-1; folder loads / sorts / mode switches reset to 0 (a chip re-sort lands on the first unjudged file).

**Cache Management**:
- `removeFileFromList()` is the centralized cleanup: array splice + purge of predictionScores/featureCache/clipCache/jxlFrameCache/featureMetadata/perceptualHashes (+ `bulkRated`, with conditional `saveBulkRatedFile()` — skipped under `{ deferBulkSave: true }`, which a batch passes to save once; + prune of `bulkRatedPairs` keys referencing the removed filename via `_bulkPairKeysReferencing(name)`) + `likeOrSkip.forget(path)` + currentIndex adjustment (a clamp only — it never shifts the index, so a batch maps its cursor by path: `LikeOrSkip.planCursorAfterBatch`). The three move sites (`moveCurrentFile`, `moveToSpecialFolder`, `moveComparePair`) call `_bulkPairKeysReferencing` BEFORE `removeFileFromList` and stash the result on the history entry as `prunedPairKeys` (omitted when empty); they, and the batch, also stash the file's `perceptualHash` (omitted when absent).
- Feature cache v4: on-disk `{vector,size,mtime,clipVector?}`; in-memory `featureCache` holds `Float32Array(64)`, `clipCache` holds `Float32Array(512)` separately; `getCombinedFeatures(path)` merges → 576-dim. `featureMetadata` Map is decoupled from `mediaFiles` so it survives moves. Stale entries pruned on load (size/mtime mismatch → re-extract). One folder visit owns it (`featureCacheStore`, [spec](docs/superpowers/specs/2026-10-21-feature-cache-wipe-design.md)): results land only in their own visit, and an unread visit saves only after its read failed, and only a copy covering every file with a CLIP vector each — "never read" once read as "0 entries" and wiped caches. main counts its writes per file (`gen`) and refuses a save based on an older one (`stale`: training wrote the source folder's file); the visit then re-reads before it saves.
- `restoreFeatureCachesFromHistory(entry)` (inverse of `removeFileFromList`): 576-dim `mlFeatures` → split into featureCache(0..64)+clipCache(64..576); 64-dim → featureCache only; the metadata takes the entry's `fileMtimeMs` (every move's history entry records it, and every undo puts the file back with it), since an entry at mtime 0 is never saved; a features restore counts as the visit's change (`featureCacheStore.markChanged()`). Also re-adds `entry.prunedPairKeys` into `bulkRatedPairs` and `entry.perceptualHash` into `perceptualHashes` (at the restored path) — BEFORE the `mlFeatures` guard, so a file with no features still gets both back. Called in every `handleCancel` branch **that reverses a file move** (and tournament undo) before the next render (`showMedia()` / `showTournamentPair()`). Not the bulk-rating undo branch — correctly, since `applyBulkRating` moves no files.
- Training-vector cache (`ml-training.js`, `MlTrainingManager`): each of the like/dislike folders gets its own `.feature_cache.json` — same v4 format, `size`/`mtime` staleness rule, streaming IO and atomic write as the source folder's — serialized through the store's IO lock (one lock, one writer, across source and training folders alike). **Isolation is load-bearing, and is enforced in two places** — the module's own entries live only in a `Map` local to the call (`_loadVectorCache`/`_saveVectorCache`), *and* the injected `computeFeatures` callback passes `{ useHostCache: false }` so the host's `computeFeatures` neither reads nor writes `this.featureCache`/`this.featureMetadata` for a training-folder path (`extractClipEmbedding` caches nothing, so `clipCache` needs no equivalent). The Map alone is not enough: without the flag the host method writes every training-folder path into `featureCache`, which puts training entries into the source folder's saves and lets its `has()` short-circuit return a vector the manager just rejected as stale. Source-folder maps are read-only to the manager (`getBulkRatedContext`) — bulk-rated files legitimately live there; training-folder files never do. Each `ensureTrainedModel` call writes one `ML training: …` line and each AI sort one `AI sort: …` line to `media-viewer-perf.log`. A folder segment's `failed=N` and `noClip=N` count files that block the model cache (`rowsFailed > 0`, or a CLIP-less row while CLIP is on → not cacheable → every sort retrains); the session log names them. Each training folder's shrink-guard baseline (`diskCount`) is independent; entries with `size`/`mtime` 0 are skipped, never written. Design: [ML pipeline spec](docs/superpowers/specs/2026-09-10-ml-training-pipeline-design.md).
- ML model cache: fingerprint-keyed, in app data (`userData/ml-model-cache.json` via `read-ml-model-cache`/`write-ml-model-cache` IPC) — not per source folder. `MlTrainingManager._readCachedModel`/`_writeCachedModel` manage `{version, entries: [{fingerprint, modelState, stats, descriptorSummary, savedAt}]}`, capped at `MODEL_CACHE_LIMIT=5` by write-recency, **not true LRU** — `_readCachedModel` is a pure `.find()` that never reorders on a hit, so only `_writeCachedModel` (reached solely on a rebuild) moves an entry to the front; an entry served repeatedly from cache but never rewritten still ages toward eviction. Writes are atomic (`.tmp` + `fs.rename`, mirrors `writeTournamentState`). `descriptorSummary` persists beside the weights so a wrong cache hit is diagnosable after the fact. Settings panel "Rebuild model" (`handleRebuildModelClick` → `mlTraining.invalidateModelCache()`) clears both the in-memory `sessionFingerprint` and the on-disk store.
- Sort cache: `saveSortCache` writes `cache[algorithm] = {algorithm, sortedPaths, timestamp, startFile}`; `applyCachedSortOrder(data, algorithm)` resolves the metric via `algorithm ?? data.algorithm` (caller wins; old caches fall through to Hamming). CLIP sort uses key `'clip'` in the unified `.sort_cache.json`. `insertNewFilesInSortedOrder` is algorithm-aware (`'clip'` → cosine over `clipCache`, else Hamming; missing-vector files end-appended) and stops after every `await` once its `isLive()` is false (`_applySimilarityOrder` passes its entry's own check, so an AI sort's Cancel never ends a similarity apply). Hash/sort cache I/O takes the run's folder. `saveHashCache` merges the file's valid entries into memory once per folder (memory wins), since `read-folder-cache` returns `null` for an unreadable file as for a missing one; it returns `false` on a failed write and leaves the warning to its caller, once per run.
- Bulk-rated cache: `.bulk_rated.json` per source folder `{version:1, good:[names], bad:[names]}`; in-memory `bulkRated` Map (filename→'good'|'bad'); hydrated in `loadFolder()` with stale-prune. `mlTraining.ensureTrainedModel()` resolves bulk-rated membership cheaply on every call (`_resolveBulkRatedFiles()`, metadata only — feeds the fingerprint) but only extracts vectors for them (`_collectBulkRatedVectors()`, reading — never writing — the source folder's own `featureCache`/`clipCache`) on the rebuild path, after both the session and model-cache tiers have missed. Buttons gate: `isCompareMode && isSortedByPrediction && !isTournamentMode`. The per-folder caches are untrusted folder content: hash-cache values must be `0`/`1` strings of at most 4096 characters, or they are recomputed. The feature cache writes only by streaming, with no single-write fallback, and `write-folder-cache` takes only `'hash'`/`'sort'`. `.hash_cache.json`, `.sort_cache.json` and `.bulk_rated.json` are written through `atomic-write.js` (unique tmp, fsync, rename, one write per file at a time).
- JXL frame cache (`jxlFrameCache`): bounded LRU, `JXL_CACHE_MAX=8` (animated entries ~77 MB); cache-hit does `delete`+`set` (move-to-end), oldest evicted over cap. Entries are MUTABLE streaming objects (`{frames (grow in place), width, height, animated, numLoops, frameCount, complete, whenComplete}`): `decodeJxl` resolves at frame-0 time; `whenComplete` settles when the stream finishes. Gate animation on `frameCount`, not `frames.length`. Worker-message routing in `_handleJxlWorkerMessage`/`_rejectJxlPending`.
- Tournament persistence: `.tournament_state.json` per source folder, `version: 2` — O(n), **history-free** (undo is session-only, in-memory, capped at `UNDO_HISTORY_CAP=100` picks; a legacy `version:1` payload still resumes, its history dropped on `deserialize`). Writes are trailing-edge **debounced single-flight** (`flush()` forces a durable write — Save & leave; `cancelPending()` drops a queued write — Discard/Apply) and **atomic** (`writeTournamentState` writes `.tmp` then `fs.rename` — no torn file on a crash mid-write). Structural-mutation writes are debounced too; a crash inside the debounce window self-heals because `reconcileWithFiles` re-runs on every tournament **resume/re-entry** (`_enterResumedTournamentUI`, idempotent) — a fresh start builds from current files and needs no reconcile. Per-pair render uses `showTournamentPairFast` (reuses the compare wrappers) instead of a full `showCompareMedia` teardown. `showTournamentPair()` is the render's single-flight, coalescing **owner**: a call during a render marks it dirty and returns the running loop's promise, which resolves when no render is pending (the engine's current pair is on screen, or the pass ended at the summary or on leaving tournament mode) and never rejects; code inside a render pass may request a render but must **never await** one (it would await its own loop — `_renderTournamentPairOnce` is the pass, and the `-1` net recurses into it, not the owner). Every tournament media failure — load error, JXL decode, missing file, first pair included — goes through `_skipFailedTournamentFile` (tracked `'prune'`, one toast, next pair requested, flags cleared), which never renders itself. Before the summary, `_pruneUnlistedEngineFiles()` drops any engine file absent from `mediaFiles` (an undo can restore a skipped file that then only draws byes), so Apply never tiers a skipped file. Saved state is validated at load (`validateTournamentState`: shape plus membership). An invalid save is treated as absent, with a notice. `SwissStrategy.deserialize` deliberately does not validate, because it restores trusted undo snapshots after the history entry is popped. Design: [render re-entry spec](docs/superpowers/specs/2026-10-07-g3-tournament-render-reentry-design.md).

**Async Patterns**:
- Extraction pause/resume: `signalUserActivity()` on nav/rating → 2s idle → `resumeExtraction()` resolves the gate promise. Generation counter `extractionRunId` — stale async callbacks return early.
- CLIP extraction: `@huggingface/transformers` runs in the MAIN process (§ Active gotchas). Chain: `initClipModel()` → `loadClipModel()` IPC (lazy, concurrent-safe, emits `clip-download-progress`) → image `extractClipEmbedding(path)` / video `extractKeyframes`+`extractClipEmbeddingBatch`; produces 512-dim unit-normalized vectors. Graceful degradation: CLIP unavailable = 64-dim only, no crash. `unloadClipModel` nulls model refs after a 30s idle grace.
- File-op guard: `_fileOpInFlight` is held by `moveCurrentFile`, `moveToSpecialFolder`, `moveComparePair`, `applyBulkRating`, `dislikeSkippedFiles` (across its confirmation dialog and every rename; refused while a sort runs) and `handleCancel` from before their first `await` until their `finally`. While it is set, every other file action is refused — ratings, special, bulk and navigation quietly (the press targets a file the user has not seen), undo with an `info` notice checked **before** the empty-history branch. The header actions — `switchMode`, both sort handlers (outside the similarity sort's Cancel, which stays live), `loadFolder` and `switchToFolder` (the change-folder button and the header recent-folders menu, before its reset), and `openRecentFolder` (before any IPC) — plus the tournament summary's Apply/Discard, the load-error toast's Remove and the similarity offer's Show refuse to START with "Wait for the move to finish" while the flag is held (one helper, `_refuseIfFileOpInFlight()`); they refuse, they do not take the flag. An AI sort ALREADY running can still apply its result mid-action, which is why `dislikeSkippedFiles` and its undo (`skipBatch` in `handleCancel`) refuse while a sort runs, why Tournament-mode entry refuses while a sort runs, and why `handleSortByPrediction` waits up to 30 s for an in-flight render or file action (`_waitForRenderIdle(…, true, isLive)`, cut short by a cancel or folder load) before it applies its order, and fails the sort rather than apply past the cap. Not `isLoading`: render handlers clear that at first paint, and `showMedia()` itself returns early on it. Handoff: a success branch that renders starts `showMedia()` before the `finally` releases the flag, and `showSingleMedia`/`showCompareMedia` set `isLoading` synchronously, so the gates hand over with no gap (exception: `showCompareMedia`'s `< 2`-files branch awaits cleanup first — the guarded compare paths handle `< 2` themselves); a branch that renders nothing releases with nothing in flight. Two methods do not render on every success: `dislikeSkippedFiles` and `_undoSkipBatch` skip the render when the screen still shows the right file, and the batch renders after a total failure if it tore a video down. **No guarded method may call another** — the inner call would be silently refused. Tournament picks/draws and `handleTournamentUndo` are deliberately outside it. `forceVideoCleanup` nulls `currentMedia` only if it is still the video it cleaned — an unconditional null clobbers the next render's element and strands `isLoading`. Each move checks its folders before any media teardown, so a refused or declined move leaves the media on screen, and the pair move checks both folders before either file moves. A refused folder check (`null`, which is distinct from missing) goes to `_refuseUngrantedFolder`, never to the create prompt. `move-file` never replaces an existing entry: it suffixes ` (n)`, and undo follows the returned `targetPath` (`_followRestoredFile`). Design: [rating-safety spec](docs/superpowers/specs/2026-10-06-g1-single-mode-rating-safety-design.md).
- Similarity sort (G2 PR 1, [spec](docs/superpowers/specs/2026-10-19-g2-hash-sort-off-renderer-design.md) § 6–8, § 16):
  - Every similarity order (a run, a cache hit, Show) reaches the screen through `_applySimilarityOrder`, which commits synchronously after a render-idle wait or declines and writes nothing — `showMedia()` returns early on `isLoading`, so a mid-render commit leaves the screen and the cursor on different files.
  - A run captures its settings and a snapshot of `mediaFiles` at the press and checks its token (`_assertSimilarityRunLive`) after every `await`; a stale run (a newer run or a folder load moved `_similarityRunGen`) writes nothing to the folder now open.
  - A run applies directly unless the user acted since the press (`SimilaritySort.userActedSince`), and then offers a sticky "Show"; every order-changing action calls `_invalidateSimilarityRun()`, which dismisses the offer and makes an in-flight Show stale.
  - Restore Order (`_restoreOriginalOrder(kind)`, shared by the similarity button and the AI toggle-off) waits for render idle, then re-checks before its synchronous commit, since another order may have committed during the wait.

- Context isolation on, sandbox off (required for file ops).

- **Folder grants:** file paths must lie inside folders the user picked in main's dialog (`path-grants.js`).

  - Fixed-name caches refuse planted links (`assertFixedPath`).
- **Renderer:** never parses built HTML (lint-enforced).
- **Saved state:** saved tournament state is validated at load.
- **Defense in depth:** a CSP, measured by `tests/e2e/security-csp-walk.test.js`, with violations sent to the session log. A navigation lock denies `window.open`. `ffmpeg`/`ffprobe` run via `runMediaTool` (`-protocol_whitelist file`).
- **Re-confirm flow:** folders saved before G1 are re-confirmed once. `refreshFolderGrants` marks them, and moves and the AI sort refuse before any media teardown.
- **App scheme (G1 I1, [spec](docs/superpowers/specs/2026-10-18-g1-i1-page-load-confinement-design.md)):** the window is served from `app://media-viewer` (`app-protocol.js`). Page-side media loads go through the same read rule as IPC (`createMediaReadRule`). The CSP is a response header (`APP_CSP` in `main.js`), and renderer network requests are cancelled.

'compare' : 'single'`; `D`/`F` resolve to different handlers per mode (compare `bothGood`/`bothBad` = ML training; tournament `bothWin`/`bothLose` = `handleTournamentDraw`, no ML) — isolation comes from the mode-keyed reverse map, not action-name uniqueness.

- Media URLs go through `MediaUrl.toMediaUrl`; never `file:` (the app origin can't load it, and `tests/media-url.test.js` fails).
- Compare mode exit: use `switchToSingleModeUI()` (non-toggling), NOT `toggleViewMode()` (re-toggles → infinite loop when <2 files). `loadFolder()` calls it before `hideDropZone()` — folders always open in single mode (compare context is folder-scoped).

The awaits alone are **not** sufficient — they fix `clipWorkerReady` at one instant, and `clipUnloadTimer` fires 30 s later — so a **CLIP lease** guards the window: `_scheduleClipUnload()` is the sole arming site and refuses while `clipLeases > 0`; `_acquireClipLease()`/`_releaseClipLease()` bracket `handleSortByPrediction` (acquire before Phase 1, release in its existing single-owner `finally`); `_handleClipUnloadTimer()` drops the timer rather than unloading under a lease, and does **not** re-arm because the release opens a fresh window itself; `initClipModel()` clears any pending unload, the model being demanded there. A lease released outside a `finally` pins ~200–400 MB for the session — nothing else arms the timer. **Acquire does not ensure**: the lease cannot un-issue an unload already in flight (the decision is made before `_handleClipUnloadTimer()`'s IPC await, and the main handler is synchronous), so a taker must also `await initClipModel()` *after* acquiring — the post-await `clipWorkerReady = false` is the truthful mirror of a model the main process has already dropped, and kickoff's `if (!this.clipWorkerReady)` guard reads that same flag.

Worker `progress` messages are routed by owner (prediction sort → card; similarity sort → left alone; neither → text). Show's new-file placement draws the card with neither sort flag set, so `updateSortProgress` hides its Cancel.

An **additive** key needs no bump, but not because `Object.assign({}, DEFAULT_SHORTCUTS[mode], custom[mode])` falls through — `checkShortcutConflict` never runs at load, so nothing notices a default added after the user's remap of the same **physical key**. `_mergeModeShortcuts()` is what makes additive keys safe: a stored remap outranks a later default wanting the same key, and the **new action is left unbound** (`null`) rather than stealing it. - JXL rendering: `object-fit` is silently ignored on `<canvas>` — `finishJxlCanvasDisplay` computes explicit aspect-preserving CSS px (scale ≤1). `computeJxlFrameSchedule` floors 0/short frames to `MIN_MS=20` (else a zero-delay setTimeout pegs the loop). `stopJxlAnimation()` runs first in `cleanupCurrentMedia()` (before the `!currentMedia` return) or a timer draws on a detached canvas. `ensureJxlWorker()` rejects via the stored `_jxlRejectReady` — never replace `_jxlReady` with a fresh `Promise.reject` (awaiters hold the old reference). `_jxlObjectURLs` is shared across single + both compare sides (safe only because compare re-renders both sides atomically). For JXL feature extraction, `new Image()` can't load `.jxl` — decode via `decodeJxl()` + a local object URL revoked `{once:true}` after load (do NOT reuse `jxlFrameToObjectURL()` URLs — revoked on `cleanupCurrentMedia()`).
- `jxl-oxide-wasm` constraints: only `encodeToPng()` exposes pixels (PNG→ImageBitmap round-trip); it is TERMINAL (read `r.duration` BEFORE it, call once, don't `r.free()` after); init with explicit `wasmBytes` (`read-jxl-wasm` IPC; it predates the app scheme, which also serves `vendor/jxl-oxide-wasm/`); spawn the worker with `{type:'module'}`.
- Tournament mode is **folder-scoped** — `loadFolder()` calls `exitTournamentMode()` BEFORE every branch, a failed or thrown listing included (after a header switch's Save & leave the engine is already gone), and nulls `tournament.engine` on both the empty and the non-empty branch, so switching folders always drops back to single mode (mirrors the compare-mode reset). A saved tournament is offered on Tournament-mode *entry*, never on folder open.
- `handleTournamentUndo` dispatches off **`engine.history`, the single chronological undo stack** — never `moveHistory` (picks don't write to `moveHistory` and it's cleared only on folder change, so any special move, even one made in single mode, would hijack every tournament undo). `engine.peekUndoEntry()` returns the newest **user** entry, skipping system `prune` entries; `kind` is `'pick'` (recordResult/recordDraw), `'special'` (a tournament-mode special-folder move, `meta` = the moveHistory entry, opaque to the engine) or `'prune'` (a system removal — the `-1` auto-prune, a load-failure skip or the pre-summary prune — absorbed by `undoUserAction()` so it never costs a press). The special branch restores the file on disk **first** and only then calls `undoUserAction()` — a failed `moveFile` is a clean no-op, not a compensating push-back.
- `engine.files` vs `strategy.files` **diverge after an untracked `removeFile()`** — `engine.files` is authoritative for `getTierBreakdown()`/`handleApply()`. The `-1` auto-prune, the load-failure skip (`_skipFailedTournamentFile`), the pre-summary prune (`_pruneUnlistedEngineFiles`) and the special-move removal pass `{trackUndo: true}` (kinds `'prune'`, `'prune'`, `'prune'` and `'special'`), recording a strategy snapshot + `filesSnapshot` so `undo()` restores `files`/`winCounts`/`byes`/`roundQueue` in full — the O(1) inverse-delta of prior picks cannot resurrect a removed file's strategy state on its own. A restored special file therefore re-pairs and reports its real tier instead of being stranded at Tier-0.
- The fifth `removeFile()` call site and the only untracked one, `reconcileWithFiles` (`tournament.js`, runs on every tournament-mode entry), stays **untracked by design** and calls `engine.clearHistory()` instead: a bulk reconcile can prune hundreds of files, and one O(n) `strategy.serialize()` snapshot each would make reconcile quadratic on a 24k-file folder. Dropping the session-only stack is O(1) and honest — `peekUndoKind()` → null, button disabled, "Nothing to undo" — and the user is told when a non-empty stack is dropped.
- A `special` entry whose disk restore fails twice is discarded outright (`engine.dropEntry()` + its `moveHistory` twin) AND the rest of the stack is cleared too (`engine.clearHistory()`) — entries still beneath it hold pre-removal `filesSnapshot`s, and undoing one (most picks are a 'delta', which never touches `strategy.files`) would resurrect a phantom into `engine.files` that's absent from `strategy.files`; pairs are drawn from `strategy`, so the phantom is never dealt into a pair and the `-1` auto-prune never catches it, leaving it over-counted by `getTierBreakdown()` and persisted by `serialize()` — clearing removes the only path there, with a toast only when it actually cost something.

## Best Practices

When modifying this codebase:
- Test file operations carefully (move/copy can cause data loss)
- Changes to preload.js require security review — **enforced** (prompts measured in auto mode): `permissions.ask` rules in `.claude/settings.json` prompt before any edit tool touches `preload.js` or a `.env` file, and the `PreToolUse` hook `.claude/hooks/guard-preload-bash.js` asks before any Bash/PowerShell command whose text names `preload.js`. Per the docs, `ask` rules prompt in every interactive mode including `bypassPermissions`, and in `dontAsk` the match is denied outright (stricter, still enforced); they do not state how a hook's `ask` behaves in `bypassPermissions` or `dontAsk`. The hook is needed beside the `Bash(*preload.js*)` rule: measured, the rule did not prompt for `cd <project dir> && … preload.js`. **Not covered**: commands run by Workflow-tool subagents (measured: `Bash` commands naming `preload.js` ran un-prompted inside a `claude-security` scan; whether the hook never ran or its `ask` was auto-resolved is not discriminated), shell writes to a `.env` file, and shell commands that change `preload.js` without naming it (`git checkout -- .`, `git stash pop`, a `*.js` glob).
- Worker changes may impact performance significantly
- The renderer file is large — search before adding duplicates
- When removing or relocating a **named** function / handler / call site, grep the whole repo for the symbol across **tests and comments** — not just live callers — and update or delete each hit before committing. The unit-only pre-commit hook won't catch a stale E2E assertion or a stale code comment. **The grep is necessary but not sufficient**: a comment that describes the old behavior in prose, without naming the symbol, survives it — also re-read every comment attached to the code you changed, whether or not it names a symbol.
- Worker exports require the conditional CJS pattern so tests can import them

## Maintenance

Manual-only, with no `AUTO-MANAGED` / `MANUAL` section markers: `revise-claude-md` and `claude-md-improver` edit the prose directly. Keep it durable-rules-only. A new rule is one sentence plus at most one "why"; history goes to DONE.md or the spec; extend an existing bullet rather than add a near-duplicate.
Audit quarterly, when the pre-commit size warning reports its byte trigger crossed, or when its tooling materially changes. Lines are not the trigger here: each rule is one line, so the line count barely moves while bytes grow. The warning's figures live in `scripts/check-claude-md-size.js`.
